# CONTENT — 章节、关卡与战斗内容

## 1. 内容层级

```text
章节/秘境 → 关卡 → 难度 → 波次/事件 → 精英/Boss → 结算奖励
```

- **章节/秘境**：主题、视觉、怪物池、主要掉落和章节规则的集合。“秘境”可作为特殊章节类型，不另造一套关卡协议。
- **关卡**：一次可选择的挑战，定义时长、地图、波次、Boss、三星条件和奖励。
- **难度**：在可读规则下改变怪物、机制与奖励，不只做数值倍增；解锁条件与首通独立记录。

## 2. 怪物分类

| 类型 | 设计职责 | 最小配置 |
|---|---|---|
| 普通怪 | 密度、包围、基础经验 | 生命、速度、碰撞、行为、掉落 |
| 特殊怪 | 改变走位或目标优先级 | 技能、前摇、冷却、危险提示 |
| 精英 | 阶段压力与优质奖励 | 强化规则、抗性、奖励组 |
| Boss | 关卡高潮与通关判定 | 阶段、技能组、时间轴、抗性、掉落 |

所有技能必须有可读前摇与反馈。复用怪物可换组合/行为，但不以颜色替换假装全新内容。

## 3. 关卡节奏

- 推荐普通关 5～10 分钟；精确时长配置化。
- 开场用于理解当局法器与首轮升级，中段通过密度/精英形成 Build 验证，末段进入 Boss 或生存目标。
- 波次按战斗时间推进；升级暂停不消耗战斗时间，未来倍速通过统一 `BattleClock` 生效。
- 存活上限、降载和屏外回收属于关卡性能预算，不得为了强度无限生成。

## 4. 星级

每关最多三星。条件从可配置条件集中选择，例如：通关、剩余生命比例、限时、特定受击次数或可选挑战。原则：

- 第一星通常为通关，保证主线进度清晰。
- 条件在开战前可见，结算逐项解释。
- 历史最高星永久保留；重复通关不能降低。
- 星级累计奖励与单关首通奖励分别记录，禁止重复领取。

## 5. 掉落与奖励

- 奖励拆分为首通、常规结算、三星、章节累计、难度首通和特殊掉落。
- 奖励表使用稳定 ID，可包含固定项和带透明权重/保底的随机组；结算记录实际产出来源。
- 失败和主动退出的保留比例配置化，并在确认/结算界面说明。
- 资源定位与产消闭环见 `ECONOMY.md`；内容文档不重复定义价格。

## 6. 内容扩展规则

新增法器、灵兽、怪物、Boss、章节时必须提供：稳定 ID、版本归属、解锁条件、核心行为、配置引用、资源预算、UI 展示、测试夹具和迁移策略。内容不得要求修改既有存档含义；删除 ID 前先迁移引用和玩家持有数据。

## 7. 美术、音效与反馈基准

- 视觉方向：清晰的东方修仙幻想，角色/法器轮廓优先于装饰细节；敌我、危险区、掉落和可交互状态有稳定色彩语义。
- 竖屏小尺寸下先保证辨识度，重要战斗信息不得只靠细字或颜色区分。
- 命中、受击、死亡、升级、突破、稀有掉落和领取需要分层反馈；震动可关闭，音量分类可调。
- 特效不得遮蔽 Boss 前摇、玩家位置或触控区；低端机提供降级档。

## 8. 当前实现

Phase 0 只有 `stage_mvp_01`、一个基础怪物和灰盒波次，没有章节选择、正式难度、精英、Boss、三星或结算奖励。V0.1 先形成战斗内容，V0.8 再完成章节关卡产品化。
