# COMBAT — 战斗、构筑与时间

## 1. 战斗目标与基础规则

战斗采用竖屏移动、自动攻击。玩家负责走位、规避、拾取和局内选择；本命法器决定基础攻击范式，功法与法宝扩展 Build。关卡通过怪潮、精英和 Boss 检验生存与输出。

Phase 0 已验证的飞剑、伤害幂等、经验守恒、暂停和对象池规则继续有效，详细实现事实见 `ARCHITECTURE.md`、`CONFIG.md` 与 T00～T14 验收记录。

## 2. 局内内容分类

| 类型 | 作用 | 生命周期 |
|---|---|---|
| 本命法器基础攻击 | 开局即有的核心攻击行为 | 由出战配置注入，贯穿当局 |
| 功法 | 主动/自动触发的攻击、防御或辅助能力 | 当局获得与升级，结算清空 |
| 法宝 | 改变规则或提供触发型被动 | 当局获得与升级，结算清空 |
| 绝学 | 法器高辨识度能力 | 由法器与当局条件激活 |
| 灵兽技能 | 出战灵兽提供的辅助行为 | 由出战快照注入 |

## 3. 升级三选一与 Build

- 经验满触发升级，战斗模拟暂停，UI 保持真实时间响应。
- 默认展示三个互不重复且当前可用的选项；候选池考虑前置、层数上限、互斥、权重和保底。
- 选择可获得新功法/法宝或强化已有内容。效果必须立即可感知，并有明确标题、描述、当前/下一层变化。
- Build 是法器、功法、法宝、绝学与灵兽技能的当局组合。首发强调少量清晰协同，不引入复杂羁绊棋盘。
- 随机由可注入随机源驱动，固定种子可复现；不得用显示名称或数组位置建立关系。

## 4. 伤害、死亡与掉落

- 伤害只有一个结算入口；生命夹紧，死亡幂等，同一实体激活实例只结算一次死亡。
- 配置 ID 表示种类，运行时 `entityId` 表示激活实例；回池再激活必须获得新 ID。
- 死亡顺序：不可交互 → 注销目标/碰撞 → 发布一次死亡事实 → 请求掉落/计数 → 回收。
- 伤害类型、暴击、元素与状态效果按版本逐步增加；V0.1 只实现支持首批 Build 所需的最小集合。

## 5. 怪物、精英与 Boss 战斗职责

- 普通怪塑造密度、移动压力和资源节奏。
- 精英拥有清晰可读的强化行为或技能，提供阶段奖励；不以单纯血量放大替代设计。
- Boss 有可识别前摇、危险区和阶段节奏，避免依赖屏外攻击；控制效果需有抗性/递减规则。
- 怪物行为、碰撞、奖励和生成均配置化，高频实体池化。

## 6. BattleClock 与未来倍速

所有战斗模拟必须经统一 `BattleClock` 语义取得时间：

```text
battleDelta = realDelta × timeScale（仅 Running）
暂停或 Ended 时 battleDelta = 0
UI、广告、服务器倒计时和平台生命周期使用 real/server time
```

- `timeScale` 设计值为 `1x / 1.5x / 2x`，计划 V1.1 实现；V1.0 及以前默认固定 `1x`。
- 解锁逻辑可由通关进度、玩家等级或便利性权益配置，但不得改变奖励概率或绕过关卡计时目标；最终规则在 V1.1 评审。
- AI、移动、武器冷却、投射物、状态持续、刷怪和战斗计时只能消费统一 battle delta，禁止各模块散落乘倍速，禁止依赖 `director` 全局缩放。
- 当前类名为 `SimulationClock`，它已承担 `BattleClock` 时间门；本次不重命名、不修改代码。未来扩展应在该单一入口增加只读 `timeScale`，而非另建并行时钟。

## 7. 暂停与平台中断

升级选择、系统暂停和平台切后台是不同原因，但都由战局状态统一裁决是否推进模拟。恢复必须避免累计超大 delta。广告期间停止战斗，广告结果通过适配层返回；不得让 UI 使用 battle delta 导致按钮冻结。

## 8. Phase 0 基线

- 状态：`Booting → Running ↔ LevelUpPaused → Ended`。
- 玩家移动、基础怪追踪、自动飞剑、伤害死亡、经验拾取、跨级队列和三选一已验证。
- 初始灰盒数值与 schema 见 `CONFIG.md`，不代表正式平衡。
- Boss、精英、正式功法/法宝/绝学、玩家受击、结算和倍速尚未实现，分别按 `ROADMAP.md` 进入后续版本。

## 9. 异常用例

- 发射前目标死亡：重验并取消或改选，不攻击回池对象。
- 同帧多次致死：只产生一次死亡、掉落和任务进度。
- 升级时在途实体：模拟冻结，选择完成后连续处理升级队列。
- 场景退出/切后台：解除监听、停止计时、回收实体；恢复不补算离线战斗。
