# UI_IA — 信息架构与交互基准

## 1. 一级信息架构

主导航规划为：首页、关卡、灵兽、修行、图鉴、任务、商店、我的。移动端可用底部主导航承载高频入口，其余从首页/更多入口进入；最终数量应经原型测试收敛，不能为了容纳全部系统而拥挤。

| 页面 | 核心信息与动作 |
|---|---|
| 首页 | 当前角色/法器、关键资源、继续挑战、活动与奖励入口 |
| 关卡 | 章节/秘境、关卡、难度、三星、掉落预览、出战准备 |
| 灵兽 | 列表、详情、等级、星级、灵魄、技能、出战 |
| 修行 | 玩家等级、境界/小境界、修为、突破、本命法器培养 |
| 图鉴 | 法器、灵兽、怪物、Boss、章节收集与详情 |
| 任务 | 主线、每日、每周、活动任务与领取 |
| 商店 | 商品分组、礼包、免费项、刷新与限购 |
| 我的 | 账号、设置、存档状态、音效/震动、隐私与客服 |

## 2. 战斗 UI

- 顶部安全区内：生命、战斗等级/经验、计时、暂停；Boss 阶段显示 Boss 生命与阶段提示。
- 主战区：玩家、敌人、投射物、危险预警和掉落，避免永久面板遮挡。
- 下部：虚拟摇杆/触控区；若有主动技能，按钮需避开系统手势区。
- 升级三选一：暂停层明确标题、三张可点击选项、层数/变化描述；防连点并兼容小屏纵向布局。
- 结算：胜负、星级、奖励分源展示、任务进度、重试/下一关/返回。

## 3. SafeArea 与小屏

- 布局基于设计分辨率与 SafeArea 动态内缩；关键按钮、资源数量和返回入口不得落入刘海、圆角、状态栏或底部手势区。
- 支持最小目标设备的窄屏/短屏；优先重排、滚动和缩略非关键装饰，不缩小关键文字与触控目标到不可用。
- 弹窗内容可滚动，主要操作保持可见；长数值使用一致缩写并可查看精确值。
- 触控热区至少覆盖视觉按钮且不相互重叠；颜色之外增加图标、形状或文字状态。

## 4. 视觉与声音

- 界面使用东方修仙语汇但保持清晰层级；品质颜色、货币图标和状态语义全局一致。
- 动效反馈服务状态变化，不阻塞连续领取；提供减少震动/关闭音效选项。
- 战斗音频按 BGM、技能、命中、UI 分组，处理同类音效并发上限，避免怪潮造成噪声与性能问题。

## 5. UI 与规则的关系

- UI 只展示产品/配置提供的状态并发出意图，不直接创造奖励、价格、解锁、伤害或概率规则。
- 概念稿用于布局与视觉参考，不是规则来源。概念稿与产品文档冲突时，以产品文档为准，并记录差异。
- 未配置或未实现的入口应隐藏/锁定并说明，禁止用假数据伪装完成。

## 6. 当前实现

V0.8 已交付并经 Creator 验收确认基础产品导航和动态灰盒面板。V1.0 的实际主导航为首页、关卡、灵兽、修行、我的；图鉴、商店及其他功能按入口和解锁配置访问。正式切图已分批接入首页、导航、关卡、灵兽、修行、战斗与结算等界面，但任务/成就/图鉴/商店/签到/奖励中心/我的页仍有灰盒控件，且整体布局、交互和资源表现尚待 Creator 验收。SafeArea 多机型矩阵、性能/包体与微信真机验收分别归 V10-13、V10-15、V10-16，状态以 `CODEX_TASKS_V10.md` 为准。
