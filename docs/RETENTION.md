# RETENTION — 任务、登录与长期目标

## 1. 目标

留存系统用于持续展示可理解目标和集中领取奖励，不用红点、倒计时或损失厌恶制造强迫。所有完成与领取状态持久化，时间规则以可信服务器时间为准。

## 2. 任务

任务统一模型包含任务 ID、类型、条件、目标值、奖励、开放条件、周期、前置和跳转目标。

- **主线/成长任务**：一次性，引导章节与培养系统。
- **每日/每周任务**：周期性，覆盖自然玩法，避免要求无意义重复或强制付费。
- **活动任务**：属于活动实例，结束后按活动规则处理未领取奖励。
- 进度由领域事件累计，必须幂等；禁止 UI 轮询游戏状态自行推断完成。

## 3. 30 日累计登录

- 以累计有效登录天数推进 1～30 档，不要求自然日连续；漏登不会清零或跳过档位。
- 每个服务器自然日最多增加一次累计登录；同日多次登录只可领取当前已解锁且未领取档位。
- 默认**不需要补签**：漏登后下一个有效登录继续推进。若未来运营采用日历式签到，补签券/灵玉补签必须作为另一活动类型，不修改累计登录语义。
- 奖励可逐日领取；第 30 日领取后本轮完成。是否循环、进入下一期或永久结束由活动配置明确，首发默认一次性新手 30 日周期。
- 跨时区、服务器日切、离线跨日和回拨时间均以服务器时间判定；客户端本地时间只用于展示倒计时。

## 4. 成就

成就是永久的一次性或分级目标，覆盖战斗、收集、成长和挑战。隐藏成就不得展示误导性红点；分级成就只显示当前阶段，历史进度保留。奖励领取与完成分离，已完成不可因配置更新回退。

## 5. 图鉴

图鉴收录法器、灵兽、怪物、Boss 和章节条目，区分“已见”“已解锁/击败”“已领取收集奖励”。未知内容可显示剪影和线索，避免提前泄露关键 Boss。图鉴是收集与知识入口，不承担正式属性规则来源；详情数据来自相应配置。

## 6. 奖励中心

结算补发、活动奖励、维护补偿和可延迟领取奖励进入统一奖励中心。每条记录包含来源、内容、生成/过期时间、领取状态和唯一 ID。过期规则需明确；付费内容、补单和系统错误补偿不得静默过期。

## 7. 红点原则

- 红点只表示“玩家当前可执行且有明确价值的动作”，不是广告曝光工具。
- 数据源为可查询状态，例如可领取、可免费升级、首次解锁；页面红点由子项聚合，不互相递归。
- 打开页面不一定清除红点；完成对应动作或明确阅读后才清除。
- 提供全局去重、优先级和循环检测，禁止每帧全树扫描。

## 8. 当前实现

任务、图鉴、30 日累计登录、成就、红点和奖励中心均属于 V0.8 产品化范围，Phase 0 未实现。
