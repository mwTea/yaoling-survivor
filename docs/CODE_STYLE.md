# CODE_STYLE — Cocos Creator / TypeScript

## TypeScript

- 开启并维持严格类型检查；公共方法写明确返回类型。
- 不使用 `any`；外部未知数据用 `unknown` 加类型守卫。
- 优先 `interface` 描述对象契约，联合类型描述有限状态；状态分支使用穷尽检查。
- 配置和事件 payload 使用 `readonly`；集合尽可能暴露只读视图。
- 文件名与主要导出一致，类/类型用 `PascalCase`，变量/方法用 `camelCase`，配置 ID 用 `snake_case`。
- 布尔名用 `is/has/can/should`；事件处理方法用 `handleXxx`；生命周期保持引擎标准命名。
- 避免深层嵌套，先处理非法状态并返回。错误信息应包含实体/配置 ID 和失败原因。
- 禁止对 Set/Map 使用数组展开（`[...map]`）：微信构建管线的 Babel loose 模式会把它编译成
  `[].concat(map)`，运行时得到 `[Map对象]` 而非键值对数组（Creator 桌面预览不复现）。
  快照迭代一律使用 `Array.from(iterable)`；`for...of` 直接遍历不受影响。数组的展开安全。
- `enum` 只用于稳定的小型状态集合；配置 ID 不用 enum，避免每加配置都改代码。

## Cocos 组件

- 组件类使用 `@ccclass('ClassName')`；序列化字段使用 `@property` 并设为 `private`。
- 序列化引用在 `onLoad` 验证并给出明确错误；高频路径缓存组件引用。
- 不在 `update()` 中执行 `find`、重复 `getComponent`、资源加载或创建临时闭包。
- 使用 `Vec2/Vec3` 时在热路径复用临时向量，避免链式方法制造垃圾。
- 事件监听使用具名方法并保留正确 `this`，确保可以精确解除。
- `schedule`/计时器必须可取消；池化对象回收和组件禁用时清理。

## 文件结构

建议顺序：导入 → 类型/常量 → 装饰器类 → 序列化字段 → 私有运行态 → 生命周期 → 公共 API → 私有方法。单文件主要只有一个业务职责；超过约 250 行或出现两个独立变化原因时评估拆分，不机械拆分。

## 注释与日志

- 注释解释“为什么/约束”，不复述代码。公开且非显然的接口写简短 TSDoc。
- 临时调试日志提交前移除。保留日志应带模块前缀，且不得在每帧/每实体热路径输出。
- 不捕获后忽略异常。可恢复错误说明降级策略；不可恢复配置错误启动时直接失败。

## 数值与常量

- 游戏数值来自配置。代码常量仅用于协议、算法 epsilon、硬安全限制等，并使用命名常量说明单位。
- 禁止含糊单位名，如 `speedPerFrame`。时间统一秒，位置/速度统一 Creator 世界单位。

## 提交粒度与验证

- 每次修改对应一个可验收任务；避免全仓格式化。
- 纯逻辑必须可在无场景环境下测试。组件任务提供 Creator 内手工验证步骤。
- 修复缺陷时先添加能复现问题的测试，若只能场景复现则记录精确步骤和期望结果。
