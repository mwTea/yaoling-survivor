# ECONOMY — 资源与商业模型

## 1. 经济原则

- 每种资源有明确来源、用途、库存上限和展示单位；避免多个资源承担相同功能。
- 免费玩家可通过持续游玩完成主线与核心养成；付费/广告主要提供可选加速、补充和外观价值。
- 奖励发放必须幂等并记录来源；扣除与发放作为一次事务保存，失败可重试但不可重复获利。
- 所有数量、价格、限购、刷新和开关配置化，客户端展示不能作为支付或奖励真相。

## 2. 核心资源

| 资源 | 定位 | 主要来源 | 主要消耗 |
|---|---|---|---|
| 灵石 | 常规软货币 | 关卡、任务、登录、活动 | 法器/灵兽常规升级、商店 |
| 灵玉 | 稀缺高级货币 | 成就、活动、合规付费/补偿 | 特定礼包、稀缺商品、便利性 |
| 修为 | 境界进度资源 | 关卡、任务、修行奖励 | 小境界提升与突破 |
| 灵魄 | 灵兽碎片型资源 | 指定关卡、活动、商店/礼包 | 对应灵兽解锁与升星 |
| 养成材料 | 内容定向门槛 | 章节、Boss、活动 | 法器、突破或技能节点 |

局内经验不是经济资源，不进入库存。账号经验只用于玩家等级，不直接作为支付货币。

## 3. 产消闭环

```text
关卡/任务/登录/活动产出
  → 库存与奖励中心
  → 法器/灵兽/境界/商店消耗
  → 战力与解锁提升
  → 挑战更高内容并获得新资源
```

V0.5 必须建立基础产消闭环后才扩大投放；V0.8 商店和礼包不能在缺少稳定消耗点时先行。数值评审同时检查每日免费产出、关键升级所需天数、资源沉淀和付费差距。

## 4. 商店

- 商店由商品组构成，支持固定、每日/每周刷新、进度解锁和限购；刷新使用服务器时间。
- 商品明确展示内容、数量、价格、剩余次数和刷新时点；随机商品需公开可能范围和必要概率信息。
- 免费领取项视为价格类型之一，领取后按周期锁定；广告商品必须在触发前说明奖励。
- Phase 0～V0.5 不实现商店；V0.8 完成基础商店产品化。

## 5. 统一礼包模型

免费、新手、成长、章节、境界和未来限时礼包统一使用同一模型：

| 字段 | 含义 |
|---|---|
| `offerId/type` | 稳定 ID 与礼包类型 |
| `contents` | 明确奖励列表/展示顺序 |
| `priceType/price` | 免费、灵玉、法币或广告；价格 |
| `unlockCondition` | 玩家等级、章节、境界、时间等 |
| `startAt/endAt` | 可售窗口，永久礼包可为空 |
| `purchaseLimit/resetRule` | 总限购与周期重置 |
| `prerequisiteOfferIds` | 成长链前置，禁止用 UI 顺序表达 |
| `featureFlagId` | 灰度/下线控制 |

- 免费礼包也走领取事务，不做独立特例系统。
- 新手礼包按账号创建/首次解锁计时；成长、章节、境界礼包根据对应进度解锁；限时礼包只扩展时间和触发条件。
- 法币支付、退款、补单、未成年人限制和价格本地化必须在 V1.0 商业化评审中确定；文档模型不等于已批准接入。

## 6. 广告边界

V1.0 候选广告位仅限明确的激励选择，如一次复活、结算额外奖励或每日有限资源。次数与冷却配置化，广告失败不扣次数，不自动连续播放。插屏默认关闭，若未来启用必须避开战斗、选择和首次核心体验，并受远程开关控制。

## 7. 防错与审计

使用整数最小单位；余额不得为负；领取/购买请求带唯一事务 ID；存档记录最近关键事务与配置版本。任何经济配置热更必须能快速关闭，且不能回收玩家已合法获得的物品。

## 8. 当前实现

Phase 0 没有局外资源、商店、礼包、广告或支付。经验守恒日志只验证局内经验物，不代表账号经济系统已实现。
