# ROADMAP — 版本路线与范围

## 1. 版本原则

版本按可独立验收的产品能力推进，不按文档中是否已设计判断完成。**设计到 ≠ 当前开发**；后续版本的 schema/接口预留不授权实现对应系统。

## 2. 路线

| 阶段 | 目标 | 主要范围 | 明确不含 |
|---|---|---|---|
| Phase 0 | 核心战斗技术底座 | T00～T14：移动、刷怪、池化、自动飞剑、伤害死亡、经验、局内等级、三选一、暂停、HUD、微信模拟器/真机验收 | 正式内容、局外成长、商业化 |
| V0.1 | 战斗玩法成型 | 首批法器方向、功法、法宝、Build、玩家受击、精英、Boss、正式战斗结算 | 完整局外经济和产品导航 |
| V0.5 | 局外成长 | 玩家等级、境界/小境界/修为/突破、法器培养、灵兽培养、基础资源产消闭环 | 完整商店/活动/正式商业化 |
| V0.8 | 完整产品化 | 章节关卡/难度/三星、任务、图鉴、商店、30 日奖励、礼包、成就、红点、奖励中心、基础活动框架 | 正式上线接入与倍速 |
| V1.0 | 微信正式首发 | 新手引导、功能解锁、微信登录/云存档、广告、正式 UI/美术/音效、SafeArea、性能/包体/埋点、合规与发布验收 | 倍速、Future 系统 |
| V1.1 | 倍速与便利性 | 1x/1.5x/2x、解锁规则、体验便利功能、完整回归 | 新大型养成系统 |
| V1.2+ | 内容运营 | 新法器、灵兽、章节、Boss、活动及平衡迭代 | 未经立项的 Future 系统 |

## 3. Phase 0 保护线

- T00～T13 已完成事实和验收结果不因路线重命名而变化。
- T14 仍为“部分完成”：微信开发者工具模拟器通过，真机验证待正式 AppID 或安卓设备。
- 本次 V0.2 文档重构不修改代码、场景、Prefab、配置实现、测试、任务边界或验收结论。
- 后续从 V0.1 开始另建任务编号与验收，不回填或扩大 T00～T14。

## 4. Future（不进入 V1.0）

经脉、复杂羁绊、装备洗练、宝石、公会、PVP、多人、赛季、通行证、离线挂机统一进入 Future。文档可预留稳定 ID、存档扩展区或模块边界，但不得提前建立玩法、UI、经济投放或通用框架。

进入路线前必须单独立项，说明用户价值、依赖、经济影响、服务/合规成本、性能预算、版本归属与删减方案。

## 5. 阶段门禁

每阶段必须同时满足：范围文档确定、可运行版本、自动检查、Creator/微信对应环境验收、性能预算、存档/配置迁移（如有）和准确进度记录。未完成项不得以“代码已写”标记完成。
