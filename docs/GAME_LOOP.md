# GAME_LOOP — 核心循环与节奏

## 1. 会话结构

玩家从首页进入关卡，选择已解锁关卡、难度、本命法器和出战灵兽；战斗中通过移动、自动攻击、经验拾取和三选一构筑成长；击败 Boss 或满足目标后结算。结算统一处理星级、首通、掉落、任务进度与账号经验，之后返回局外进行培养或继续挑战。

## 2. 单局流程

```text
准备 → 开局教学/倒计时 → 常规怪潮 → 升级构筑
     → 精英/节奏事件 → Boss → 胜负结算
```

- 推荐首发单局目标为 5～10 分钟，具体由关卡配置决定；中断恢复能力在 V1.0 根据微信生命周期验证后决定。
- 常规战斗提供稳定经验与掉落；精英提供阶段压力和较高价值选择；Boss 检验走位、伤害和 Build 完整度。
- 战斗等级从每局初始值开始，局内经验达到阈值触发三选一；所有未持久化局内效果在结算或退出后清除。
- 关卡胜利、失败、主动退出、复活后的结算差异必须清晰可见，禁止隐藏扣减。

## 3. 局外循环

```text
领取结算/任务/登录奖励
  → 消耗资源提升玩家、境界、法器或灵兽
  → 更新出战配置
  → 挑战新关卡、补三星或刷目标材料
```

局外每次操作都应回答“消耗什么、提升什么、下一目标是什么”。系统解锁以玩家进度为主、账号创建天数为辅，不用大量同时弹窗打断。

## 4. 功能逐步解锁

| 节点 | 解锁目的 | 规则原则 |
|---|---|---|
| 首次进入 | 首页、关卡、基础法器 | 直接开始第一局，不展示全部入口 |
| 首次升级 | 局内三选一 | 强引导一次，之后弱提示 |
| 首次结算 | 玩家等级、任务/奖励中心 | 解释奖励去向 |
| 章节推进 | 修行、灵兽、图鉴、商店 | 每次最多重点介绍一个新系统 |
| 中后期 | 活动、礼包、便利功能 | 由功能开关与条件共同控制 |

精确解锁条件配置化，不在 UI 代码中硬编码。未解锁入口可隐藏或显示明确条件，但不得形成无解释红点。

## 5. 新手引导原则

- V1.0 提供“操作 → 自动攻击 → 拾取 → 三选一 → 结算 → 首次培养”的最短闭环。
- 强制步骤只用于不可逆或首次核心操作；允许跳过的说明不阻塞战斗。
- 引导系统只引用产品规则和配置 ID，不从 UI 概念稿反推规则。
- 记录步骤版本和完成状态；改版后通过迁移策略避免老玩家重复卡住。

## 6. 失败、重试与复活

失败页明确展示失败原因、已获得奖励、提升建议和重试入口。V1.0 已实现可选激励广告复活：每局/每日次数、无敌时间、恢复比例和不可用关卡均配置化；不观看不影响既得奖励。模拟广告链路已实现，正式广告位真机验收仍待完成；Phase 0 不实现复活。

## 7. 当前实现映射

Phase 0 的移动、刷怪、自动攻击、击杀、经验拾取与升级三选一底座，以及 V0.1～V0.8 的战斗内容、账号成长和关卡外循环均已实现；V0.8 的 12 关、三章节、难度/三星/章节里程碑和结算产品化已通过 Creator 验收。

V1.0 正在收口：V10-01～V10-12 的存档、解锁、引导、平台适配、广告和埋点有实现记录，当前仍待相应 Creator、云环境或真机验收。测试期按用户决定关闭新手引导与音效。V10-14 的正式 UI/美术接入和战斗 P0 修正仍待 Creator 逐页复验；后续顺序为 V10-17 构筑扩展、V10-13 SafeArea、V10-15 性能/包体与 V10-16 发布验收。任务级状态以 `CODEX_TASKS_V10.md` 为准，勿将“实现完成，待验收”视为已验收。
