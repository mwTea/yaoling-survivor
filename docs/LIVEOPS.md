# LIVEOPS — 活动、时间与运营控制

## 1. 服务器时间

- 登录、日切、限时活动、商店刷新、礼包窗口和奖励过期以可信服务器时间为准。
- 客户端保存最近一次服务器时间与单调时钟偏移，仅作短时展示/容错；检测明显回拨时不自行发奖，进入安全降级并待校时。
- 统一提供 `ServerTimeService` 语义，业务不得各自读取本地日期。Phase 0 无服务器，本次只定义边界，不实现伪服务器时间。

## 2. 功能开关

功能开关至少包含稳定 ID、默认值、平台/版本条件、开放时间、玩家分群、紧急关闭和配置版本。原则：默认安全、关闭可降级、关键经济开关可快速止损；客户端不把开关当安全权限。

V1.0 前允许使用随包静态配置形成同一接口，正式运营再接远程配置；不得为 Future 系统提前引入大型热更新框架。

## 3. 活动统一模型

活动实例由活动 ID/类型、展示窗口、参与窗口、结算窗口、解锁条件、任务/兑换/奖励引用、入口、红点规则和功能开关组成。首发只实现能复用的基础活动壳，不为每个活动复制一套领取和倒计时逻辑。

未来限时礼包、活动任务和登录活动复用各自基础模型，通过活动实例编排；礼包规则见 `ECONOMY.md`，30 日累计登录见 `RETENTION.md`。

## 4. 红点与奖励中心

活动红点必须来自“新开放、可参与、可领取”等明确状态，并接受全局红点原则。活动关闭后，未领取奖励按配置进入奖励中心或过期；处理结果必须可审计，不得仅靠弹窗补发。

## 5. 账号与存档

### 数据域

- 身份：本地访客标识、微信登录标识、账号创建与最后登录时间。
- 进度：玩家等级、章节/关卡/难度、最高星、引导与功能解锁。
- 养成：境界、修为、法器、灵兽、库存与编队。
- 留存/运营：任务、成就、登录、活动、红点阅读、奖励中心、购买/广告次数。
- 设置：音量、震动、画质、语言预留与协议版本。

### 保存原则

- V1.0 提供微信登录与云存档；本地缓存用于启动和断网容错，不是多端最终真相。
- 存档带 schema/version、更新时间、校验与迁移；关键事务幂等。发生冲突时展示可理解选择或按已评审策略合并，禁止静默用旧档覆盖新档。
- 战斗局内快照与账号存档分离。默认不承诺离线挂机，也不通过修改本地时间产生收益。
- 隐私、授权、删除账号、未成年人和数据最小化遵守微信平台及上线地区要求。

## 6. 广告与埋点运营边界

- 广告由平台适配层承接加载、展示、关闭、失败和奖励凭证；业务只消费明确结果。
- 关键埋点覆盖新手漏斗、开局/结算、失败原因、Build 选择、资源产消、广告与购买结果；不得采集无必要个人信息。
- 埋点失败不阻断游戏，批量与频率需控制包体、网络和性能。

## 7. 当前实现

Phase 0 没有服务器时间、远程开关、活动、账号登录、云存档、广告或正式埋点。V0.8 建立产品化模型，V1.0 接入首发必需能力。
